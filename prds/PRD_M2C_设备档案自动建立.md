# PRD：M2-C 设备档案自动建立（P2 装备售后全旅程闭环）

> 版本 v1.0 ｜ 2026-08-14 ｜ 锚定场景 S07（评分 83.4，见 `docs/research/场景调研_27选9.md`）

## 1. 场景锚定
S07 空压机装机验收档案（83.4）＞ S09 二手设备评估（80.1）＞ S08 移机档案（78.9）。
**选 S07**：与 S01/S04 构成"装机→运维→哨兵"同行业闭环；是用户 D 方向（数据脏乱差）的场景化落位。落选理由：S08 低频；S09 偏交易评估域。

## 2. 产品定位（一句话）
装机验收单 30 秒变结构化设备档案：解析→预填→冲突高亮→人工确认→自动纳入保养与监测，消灭售后 AI 的"数据搬运第一公里"。

## 3. 目标用户与痛点
- 用户：厂商客服/档案管理员（录入）、售后工程师（档案消费方）。
- 痛点（量化假设）：装机单手写+拍照+PDF 混排，单份录入 ≥30 分钟且易错；新机未及时入监测导致保养提醒漏发；保内保外判定纠纷。

## 4. Agent 编排（3 Agent）
| Agent | 职责（微循环内自主） |
|---|---|
| 文档理解 Agent | 版面分析+表格/字段抽取+手写 OCR，输出带来源坐标与置信度 |
| 校验对齐 Agent | 与主数据匹配（机型/序列号）、单位与料号规范校验、冲突高亮 |
| 发布 Agent | 待确认清单生成 →（人工审核后）写入档案库+注册保养基线与监测订阅 |

- **微循环定义**：文档上传→解析→预填+冲突高亮，全程自主。
- **宏门禁点**：①档案定稿入库（工程师确认）②写入下游系统前的留痕审核。

## 5. 任务闭环 7 步映射（手册 8.2）
输入=多格式装机/验收文档 → 意图理解=文档类型与字段集识别 → 任务规划=解析与校验计划 → 能力调用=OCR/版面分析/主数据 API → 结果交付=结构化档案+置信度+冲突清单 → 验证反馈=字段级准确率统计+人工修正量 → 安全边界=数据授权与全程留痕。

## 6. 数据策略
自造 20-30 份多格式样例（手写装机单、Excel 验收表、PDF 铭牌照片），版权干净；字段级 ground truth 人工标注；PaddleOCR/LayoutLM 系开源工具做基线（许可待核验）。

## 7. 评测指标
字段级准确率：打印件 ≥95%、手写件 ≥85%；人工修正字段比例 ≤10%；单份处理 ≤60 秒；档案注册后保养提醒触达率 100%。

## 8. 安全合规口径
低风险建议域；样例不含真实客户信息；修正与写入全程留痕可审计（手册 8.1-5/8.1-6）。

## 9. 三档赛事排期
- 初赛（8.16 前）：作为 P2 叙事"数据底座"一页（保底 PPT 已含架构位）
- 复赛（9.3 前）：文档→档案演示链（时间富余时作为第二演示链）
- 决赛（9.22）：现场上传新样例即时解析，展示置信度与人工确认闭环

## 10. 开源复用物
装机单字段 schema、文档理解抽取模板（Prompt+后处理）、多格式样例集。

## 11. 风险与对策
手写识别不稳 → 置信度分级+人工修正环节本身是产品特性（8.1-6 人工确认机制的正面展示）；场景价值分偏低 → 叙事绑定"售后 AI 的第一公里"与 P2 主线。

## 12. 参赛简介（≤500 字，八要素）
**项目名称**：气脉建档 AirDoc——装备装机验收档案数字化智能体。
**行业赛题**：AI+工业制造。**目标用户**：装备厂商客服、档案管理员与售后工程师。
**核心问题**：装机验收单手写、拍照、PDF 混排，档案录入滞后易错，设备未及时纳入保养与监测。
**解决方案**：三 Agent 流水线——文档理解 Agent 做版面分析与字段抽取（带来源坐标与置信度），校验对齐 Agent 匹配主数据并高亮冲突，发布 Agent 生成待确认清单并在人工审核后写入档案库、自动注册保养基线。
**创新点**：每个字段可溯源（来源坐标+置信度），人工确认内建为产品环节；正面解决"数据脏乱差挡住 AI 提效"的行业堵点。
**开放/复用价值**：开源装机单 schema、抽取模板与多格式样例集，可迁移至其他装备与工程文档场景。
**当前进展**：样例集制作与原型开发中，提交时附解析演示。
