# PRD：M3-B 缺料请购联动（P3 计划协同副驾）

> 版本 v1.0 ｜ 2026-08-14 ｜ 锚定场景 S16（评分 85.9，见 `docs/research/场景调研_27选9.md`）

## 1. 场景锚定
S16 机械/汽配周度请购（85.9）＞ S17 MRO 备件（84.7）＞ S18 包材（82.3）。
**选 S16**：与 S17 分差 1.2<3 → D2 定夺（均 4.5 平）→ 取总分；与 S10/S13 同厂，是 M3-A 缺口的自然延伸。落选理由：S17 品类杂但偏库存消耗逻辑；S18 物料域简单痛点轻。

## 2. 产品定位（一句话）
采购员的请购起草员：缺口→请购包+比价矩阵→审批流→下单后跟踪回写，起草全自动、下单人拍板。

## 3. 目标用户与痛点
- 用户：采购员（主用户）、物控（缺口来源）、采购经理（审批）。
- 痛点（量化假设）：单张请购单手工制作 ≥30 分钟；比价信息散落在邮件与聊天记录；下单后交期变化靠人肉跟踪。

## 4. Agent 编排（3 Agent）
| Agent | 职责（微循环内自主） |
|---|---|
| 缺口监听 Agent | 接收 M3-A 缺口清单（或独立运行简化 MRP），按紧急度×断料风险分级 |
| 请购起草 Agent | 请购单草案+比价矩阵（价格/交期/历史绩效/风险分），字段级引用来源 |
| 跟踪回写 Agent | 下单后交期变化监测→异常提醒→到货回写模拟库存 |

- **微循环定义**：缺口产生→分级→起草→比价→跟踪更新，全程自主。
- **宏门禁点**：①下单（采购员）②供应商选择（采购/经理）③紧急空运等高成本动作（经理审批）。

## 5. 任务闭环 7 步映射（手册 8.2）
输入=缺口清单/交期事件 → 意图理解=物料、数量与紧急度 → 任务规划=请购与比价计划 → 能力调用=BOM/库存/供应商库/价格历史 → 结果交付=请购包+比价矩阵 → 验证反馈=交期达成率统计与异常捕获 → 安全边界=商业决策全部人工。

## 6. 数据策略
复用 S10 模拟数据域（BOM/库存/在途）+供应商库模拟 10 家（价格带、交期分布、历史绩效、风险分）；审批流用开源工作流模板（Odoo 采购参考，待核验许可）；模拟逻辑写入合规文档。

## 7. 评测指标
请购包字段完整率 100%；比价矩阵每料覆盖 ≥3 家供应商；紧急缺口（T+3 内断料）起草时长 ≤5 分钟；交期异常捕获率 100%（剧本口径）。

## 8. 安全合规口径
不产生真实订单；价格与合同信息均为模拟并披露；比价结论附来源与假设（手册 8.1-6、9.3）。

## 9. 三档赛事排期
- 初赛（8.16 前）：作为 P3 叙事"行动闭环"一页
- 复赛（9.3 前）：与 M3-A 串联演示（齐套缺口→请购包→审批）
- 决赛（9.22）：完整"计划-哨兵-请购"同厂链路展示

## 10. 开源复用物
请购单与比价矩阵 schema、审批流模板、缺口分级规则。

## 11. 风险与对策
功能显单薄 → 强绑定 M3-A/C 联动叙事（本 MVP 定位即"动作闭环补全者"）；规则感重 → 突出交期异常跟踪与比价解释；审批演示僵硬 → 预置三种审批分支（通过/驳回/改量）。

## 12. 参赛简介（≤500 字，八要素）
**项目名称**：齐购 QiBuy——缺料请购联动智能体。
**行业赛题**：AI+工业制造。**目标用户**：中小机械/汽配厂采购员与物控。
**核心问题**：请购单手工制作、比价信息散落、下单后交期变化靠人肉跟踪。
**解决方案**：三 Agent 联动——缺口监听 Agent 接收齐套核算缺口并按紧急度与断料风险分级；请购起草 Agent 生成请购单草案与多供应商比价矩阵（价格、交期、历史绩效、风险分）；跟踪回写 Agent 盯交期异常并回写库存。
**创新点**：与齐套计划、供应商风险哨兵同厂闭环，缺口到请购包分钟级起草；下单与供应商选择始终由采购拍板，紧急高成本动作需经理审批。
**开放/复用价值**：开源请购与比价 schema、审批流模板与缺口分级规则，可直接接入中小厂采购流程。
**当前进展**：方案设计完成，原型开发中，提交时附联动演示。
