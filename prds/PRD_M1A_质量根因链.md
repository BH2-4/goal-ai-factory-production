# PRD：M1-A 质量根因链（P1 厂内异常闭环中枢）

> 版本 v1.0 ｜ 2026-08-14 ｜ 锚定场景 S19（评分 90.7，见 `docs/research/场景调研_27选9.md`）

## 1. 场景锚定
S19 半导体/精密机加 SPC 根因（90.7）＞ S21 化工 TEP（86.4）＞ S20 注塑工艺（85.2）。
**选 S19**：SECOM 公开数据集+自建四表证据链最硬；离散制造贴"批次-工单"叙事；根因引擎可复用给 P2 的 M2-B（售后 8D）。落选理由：S21 是学术常见基准、差异化弱；S20 注塑工艺 AI 商业方案多。

## 2. 产品定位（一句话）
质量工程师的根因侦探：SPC 告警→四源数据追溯→假设逐条验证→8D 初稿，把"翻五个系统找原因"压成一个按钮。

## 3. 目标用户与痛点
- 用户：半导体/精密机加厂质量工程师（主用户）、工艺/设备工程师（协同）。
- 痛点（量化假设）：单批异常根因定位 4-48 小时（跨 QMS/MES/工艺/设备四系统）；8D 报告写作 2-4 小时；同类异常复发因复盘缺失。

## 4. Agent 编排（4 Agent）
| Agent | 职责（微循环内自主） |
|---|---|
| 值守 Agent | 监听 SPC 控制图告警与规则触发，判定异常类型与影响面 |
| 数据侦探 Agent | 四源拉取与对齐：批次谱系/工艺参数窗口/设备日志/来料检验 |
| 根因推理 Agent | 假设生成→逐条验证→证据链+置信度排序，"未验证假设"单列 |
| 8D 撰写 Agent | D1-D8 结构化初稿，附证据引用与人工待办（D4 根因确认留白） |

- **微循环定义**：单次告警触发的"追溯-归因-草稿"推理链全程自主。
- **宏门禁点**：①根因确认（质量工程师）②处置措施与批次放行（质量负责人）。

## 5. 任务闭环 7 步映射（手册 8.2）
输入=SPC 告警/人工触发 → 意图理解=异常类型、批次与影响面 → 任务规划=四源追溯计划 → 能力调用=QMS/MES/工艺库/设备日志查询工具 → 结果交付=证据链+8D 初稿 → 验证反馈=历史注入案例回放命中率+工程师确认 → 安全边界=不替代放行与停线决策。

## 6. 数据策略
UCI SECOM（1567×591，含缺陷标签）做检出与特征归因展示；自建四表模拟数据集（批次谱系/工艺参数/设备日志/来料检验）并注入已知根因作 ground truth；模拟逻辑写入合规文档（FAQ Q7）。

## 7. 评测指标
注入根因 Top-3 命中率 ≥80%；证据引用准确率 ≥95%（人工抽检）；8D 字段完整率 100%；单次追溯时长 ≤10 分钟（对比人工小时级，模拟口径）。

## 8. 安全合规口径
仅辅助分析：不替代质量负责人对批次放行/停线的判断（手册 9.3、FAQ Q13）；数据为公开+模拟并披露；证据链可追溯可审计。

## 9. 三档赛事排期
- 初赛（8.16 前）：P1 叙事页（根因链为 P1 主链）
- 复赛（9.3 前）：质量一条链可运行（告警→证据链→8D→措施工单草案）
- 决赛（9.22）：现场注入新告警演示+引擎复用说明（喂给 M2-B 售后 8D）

## 10. 开源复用物
制造四表模拟器（含根因注入）、根因推理 Prompt 与验证工具模板、8D schema。

## 11. 风险与对策
归因准确性质疑 → 注入式 ground truth 评测自证；报告模板化 → 证据引用+未验证假设清单+人工修订闭环；四源数据展示复杂 → 归因时间轴+相关性矩阵可视化。

## 12. 参赛简介（≤500 字，八要素）
**项目名称**：质源侦探 RootCause Cop——质量异常根因追溯智能体。
**行业赛题**：AI+工业制造。**目标用户**：半导体与精密机加厂质量工程师。
**核心问题**：SPC 告警后需跨质检、批次、工艺、设备四套系统人工比对，根因定位数小时至数天，8D 报告耗时。
**解决方案**：四 Agent 链——值守 Agent 监听 SPC 告警；数据侦探 Agent 对齐批次谱系、工艺参数、设备日志与来料检验四源数据；根因推理 Agent 生成假设并逐条验证，形成带置信度的证据链；8D 撰写 Agent 产出结构化初稿并预留人工确认位。
**创新点**：每个结论附证据链与"未验证假设"清单，解释性内建；根因确认与批次放行始终由质量负责人拍板；引擎可复用于售后批次分析。
**开放/复用价值**：开源四表模拟器（含根因注入）、根因模板与 8D schema。
**当前进展**：方案设计完成，基于公开数据集的原型开发中，提交时附追溯演示。
