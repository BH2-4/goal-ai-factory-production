# PRD：M1-B Andon 值守循环（P1 厂内异常闭环中枢）

> 版本 v1.0 ｜ 2026-08-14 ｜ 锚定场景 S22（评分 89.3，见 `docs/research/场景调研_27选9.md`）

## 1. 场景锚定
S22 机加车间混合 Andon（89.3）vs S23 SMT（88.5，差 0.8<3 → D2 均为 5 平 → 取总分）；S24 食品灌装（84.0）。
**选 S22**：UCI AI4I 2020 数据集支撑最硬；与 M1-E（S25）同车间同数据流。落选理由：S23 电子参赛密度高；S24 卫生合规面宽、叙事偏离装备制造。

## 2. 产品定位（一句话）
机加车间的异常中枢：设备/质量/缺料事件流→自动分诊→派单→超时升级→关闭复盘，把"现场吼人+微信群"变成可解释、可配置的值守循环。

## 3. 目标用户与痛点
- 用户：产线主管/班组长（响应决策）、维修工程师（工单接收）、车间主任（复盘消费方）。
- 痛点（量化假设）：异常平均响应 ≥30 分钟；升级靠人盯，超时无兜底；处理记录散落微信群，事后无结构化数据。

## 4. Agent 编排（4 Agent）
| Agent | 职责（微循环内自主） |
|---|---|
| 分诊 Agent | 事件流分类（设备/质量/缺料）+严重度分级，可融合现场照片辅助判断 |
| 调度 Agent | 技能矩阵×班次×当前负荷 → 通知对象与升级策略（含备件关联） |
| 工单跟踪 Agent | 超时自动升级（ configurable SLA），处理记录结构化 |
| 复盘 Agent | 异常 Pareto、复发预警、SOP 修订建议（数据喂给 M1-E） |

- **微循环定义**：事件流入→分诊→派单→超时升级→关闭，值守循环全程自主。
- **宏门禁点**：①停线决策（主管）②结案确认（发起人/主管）。

## 5. 任务闭环 7 步映射（手册 8.2）
输入=设备告警/质量超标/缺料事件流 → 意图理解=分类与严重度 → 任务规划=响应与升级策略 → 能力调用=排班表/技能矩阵/备件库/SOP 库 → 结果交付=处理卡+工单+通知 → 验证反馈=关闭确认+响应时长统计 → 安全边界=停线与结案人工。

## 6. 数据策略
UCI AI4I 2020（1 万条合成、5 类故障模式）驱动设备告警流；自建事件流/排班/技能矩阵/SLA 规则模拟；照片分诊用公开设备图。模拟逻辑写入合规文档（FAQ Q7）。

## 7. 评测指标
分诊准确率 ≥85%（ground truth 事件集）；模拟平均响应时长较"人工分诊"基线下降 ≥40%；升级策略执行率 100%（无超时遗漏）；复盘 Pareto 与人工统计一致。

## 8. 安全合规口径
不控制任何真实设备；停线、重启等动作仅生成建议并要求人工确认（手册 9.3、FAQ Q13）；事件数据为公开+模拟。

## 9. 三档赛事排期
- 初赛（8.16 前）：P1 叙事页（值守循环骨架图）
- 复赛（9.3 前）：事件面板可运行（回放模式：注入事件流看分诊-派单-升级全程）
- 决赛（9.22）：实时事件注入+照片分诊多模态演示+与 M1-E 沉淀联动

## 10. 开源复用物
Andon 事件 schema、分诊规则与升级策略 DSL、事件流模拟器。

## 11. 风险与对策
做成"通知机器人" → 分诊可解释面板+升级策略输出为产品核心；事件模拟工作量大 → 复用 AI4I 合成数据；照片分诊不稳 → 定位为"辅助信号"而非依赖项。

## 12. 参赛简介（≤500 字，八要素）
**项目名称**：安灯中枢 AndonCop——车间异常响应值守智能体。
**行业赛题**：AI+工业制造。**目标用户**：机加车间产线主管、班组长与维修工程师。
**核心问题**：设备、质量、缺料异常响应靠现场吼人与微信群，责任漂移、超时无人升级、事后无结构化数据。
**解决方案**：四 Agent 值守系统——分诊 Agent 对事件流分类分级（可融合现场照片）；调度 Agent 按技能矩阵与负荷派单并生成升级策略；工单跟踪 Agent 超时自动升级并结构化处理记录；复盘 Agent 输出 Pareto 与复发预警。
**创新点**：事件驱动微循环全程自主，停线与结案由主管拍板；升级策略可解释、可配置，避免"通知机器人"化。
**开放/复用价值**：开源事件 schema、分诊与升级策略模板、事件流模拟器，可迁移至各类车间。
**当前进展**：方案设计完成，基于公开数据集的原型开发中，提交时附回放演示。
