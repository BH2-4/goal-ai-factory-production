1.2 赛道介绍

  【无界应用｜Boundless Agents】赛道聚焦 AI Agent 在真实行业场景中的落地应用，鼓励参赛团队

围绕个人终端、汽车出行、金融服务、教育、工业制造等高频场景，构建具备任务理解、流程编排、工具

调用、知识增强、多轮交互和结果交付能力的智能体应用。同时，特别欢迎具备多模态能力的参赛作品。

  本赛道不鼓励泛聊天机器人、单点问答工具或简单内容生成器，而是希望参赛作品能够面向真实用户、

真实业务流程和真实任务闭环，验证 AI Agent 如何进入行业现场，提升效率、改善体验，并形成具备持

续使用价值的应用雏形。

  参赛作品可基于大模型、Agent 框架、行业知识库、工具调用、多模态交互、工作流编排等技术能力

构建。除具体赛题另有要求外，开发框架、模型和工具平台原则上不作强制限制。

1.3 核心参赛要求

     参赛作品应至少完成一个可演示、可验证的任务闭环，并清楚说明目标用户、场景痛点、交互流程、

技术路线、数据来源、合规边界和后续迭代计划。

    面向五大行业赛题之一，或基于真实需求提出与赛道定位一致的细分场景；

    避免仅做泛问答、内容生成或没有用户流程的概念展示；

    具备可运行 Demo、视频演示或等价可验证材料；

    说明所使用模型、Agent 架构、工具接口、知识库、数据处理与部署方式；

    对数据授权、隐私保护、风险提示和行业边界进行明确说明；

    鼓励形成可开放、可复用的应用模板、工具组件、示例数据或技术文档。


1.4 参赛对象与适合团队

     本赛道面向全球开发者、创业团队、高校学生、科研团队、企业技术团队、产品团队及开源社区成员

开放。参赛团队可由个人或多人组成，鼓励跨学科、跨专业组队。

    AI 工程师、前后端开发者、产品经理、设计师、行业专家；

    高校学生与研究人员、开源项目贡献者、创业团队成员；

    熟悉眼镜、汽车、金融、教育、工业制造等行业场景的团队；

    能够围绕真实用户需求完成交互设计、数据准备、工具调用和结果验证的团队；

    具备产品表达、路演展示、技术文档和开源协作经验者优先。

4.3.1 AI+眼镜｜下一代个人智能终端原生智能体

●    出行辅助 Agent：路线提醒、环境信息提示、语言翻译、实时问答和行程辅助。

●    学习陪伴 Agent：知识解释、重点记录、术语查询、学习计划和复习提醒。

●    工作效率 Agent：提词、会议记录、现场巡检、摘要生成、待办整理和信息检索。

●    运动健康 Agent：运动提醒、动作反馈、节奏建议和安全提示。

●    生活消费 Agent：购物、餐饮、社交、旅行、日常提醒中的个性化建议和即时辅助。

边界要求：作品应突出 AI 眼镜的设备特性，避免简单复刻手机 App、网页应用或普通 AI 聊天工具。如

使用 Rokid 眼镜，可通过「融合录屏」功能录制智能体 Demo。


4.3.2 AI+汽车｜面向车主全生命周期的智能用车 Agent

●    智能购车顾问 Agent：车型推荐、配置对比、购车方案生成和试驾预约引导。

●    车主用车助手 Agent：车辆功能、保养周期、能耗分析、故障提示和保险服务。

●    长途出行规划 Agent：路线、天气、充电 / 加油、休息点、同行人需求和行李安排。

●    智能座舱陪伴 Agent：根据驾驶场景、乘客角色、时间状态和用户偏好提供内容与服务。

●    售后服务 Agent：问题描述、初步排查、维修预约、进度查询和售后反馈整理。

边界要求：本赛题不要求作品直接接入真实车辆控制系统，不鼓励涉及高风险驾驶控制、自动驾驶决策或

影响车辆安全的操作。

4.3.3 AI+金融｜面向企业经营与风险研判的金融服务 Agent

●   中小企业经营画像 Agent：生成经营画像、风险提示和服务建议。

●   信贷材料预审 Agent：识别贷款材料缺失项、格式问题和关键风险点。

●   投研信息整理 Agent：对公告、财报、新闻、研报和行业数据进行摘要、对比与追踪。

●   保险理赔辅助 Agent：解释理赔流程、检查材料缺失项并生成清单和提醒。

●   金融合规问答 Agent：基于制度文件或模拟规则库查询业务边界和合规注意事项。

边界要求：本赛题强调金融辅助场景，不鼓励直接提供确定性投资建议、信贷审批结论、保险赔付结论或

其他替代专业机构决策的内容。


4.3.4 AI+教育｜面向个性化学习与教学辅助的教育 Agent

●   个性化学习规划 Agent：根据学生目标、知识基础、练习表现和学习时间，生成阶段性学习计划，

    并动态调整学习路径。

●   作业辅导 Agent：面向数学、英语、编程、科学等学科，提供分步骤提示、错因分析、知识点回顾

    和同类题训练，而非直接给出答案。

●   学情诊断 Agent：基于练习记录、测试结果、课堂表现或模拟数据，识别学生知识薄弱点，生成学

    情分析报告和改进建议。

●   教师备课 Agent：辅助教师生成课程大纲、课堂活动、案例素材、板书结构、课后练习和分层教学

    方案。

●   阅读与语言学习 Agent：面向阅读理解、外语学习、口语训练、写作修改等场景，提供词汇解释、

    语法反馈、表达优化和学习记录。

●   职业教育 / 编程教育 Agent：围绕岗位技能、项目实训、代码练习、面试准备等场景，提供任务拆

    解、过程指导、反馈评价和学习路线建议。

边界要求：作品应体现“因材施教”的能力，避免简单题库问答、标准答案生成器或泛聊天陪伴工具；如

涉及学生数据、作业数据、测评数据或学习记录，应使用公开数据、模拟数据或经授权脱敏数据，不得替

代教师、学校或专业机构的最终教育评价。

4.3.5 AI+工业制造｜面向设备运维与供应链协同的工业 Agent

●   设备故障诊断 Agent：基于传感器数据、报警记录、维修手册和历史工单辅助判断故障原因。

●   质量异常分析 Agent：关联质检数据、批次信息、工艺参数和生产记录定位异常来源。

●   工单调度 Agent：根据问题类型、人员技能、备件库存、紧急程度和产线状态生成分派建议。

●   供应链风险预警 Agent：基于订单、库存、供应商交付周期、物流状态和需求变化提示风险。

●   生产计划辅助 Agent：结合产能、物料、设备状态、人员排班和交期要求生成排产建议。

边界要求：如涉及安全生产、设备控制或现场操作建议，应明确提示仅作辅助参考，不替代专业人员判断

和企业安全规范。

08 作品基本与技术要求

本章为跨阶段通用技术要求。初赛阶段可重点说明设计思路，复赛和决赛阶段需逐步形成可运行、可验证

的工程材料。


8.1 作品基本要求

1.   面向真实场景：作品应围绕具体用户、具体任务和具体行业流程展开，能够说明目标用户是谁、要解

     决什么问题、为什么需要 Agent 来解决。

2.   具备 Agent 能力：作品应体现智能体在任务理解、多轮交互、任务拆解、工具调用、知识增强、上

     下文管理、流程编排或结果交付中的能力。不建议仅提交普通聊天机器人、单轮问答工具、Prompt 演

     示或简单内容生成器。

3.   形成任务闭环：作品应至少完成一个完整任务链路，例如从用户咨询到方案生成、从材料输入到预审

     反馈、从学习诊断到路径规划、从异常发现到工单建议、从出行需求到路线规划和提醒。

4.   具备可演示性：作品需能够通过视频 Demo、在线系统、可运行环境、代码仓库、模拟数据或等价材

     料进行验证。进入复赛 / 决赛后，应按组委会要求提供评审可访问的工程材料、Demo、运行证据或

     等价可验证材料。

5.   数据来源清晰：作品使用的数据、文档、知识库、接口、模型或第三方平台，应说明来源、授权方式、

     处理方式和使用边界。使用模拟数据时，应说明模拟逻辑和适用范围；使用真实数据时，应完成必要

     授权、脱敏和合规处理。

6.   边界表达清楚：涉及金融、教育、工业、汽车、个人终端等场景时，作品应明确说明使用边界、风险

8.2 Agent 应用闭环要求

1.   任务输入：系统接收来自用户、行业数据、文档、传感器、业务表单或外部系统的任务输入。

2.   意图理解：Agent 识别用户目标、关键约束、上下文信息和风险边界。

3.   任务规划：将用户目标拆解为可执行步骤，并说明是否需要工具、知识库、人工确认或外部系统。

4.   能力调用：根据作品需要调用模型、知识库、API、数据库、业务系统或多模态能力完成关键环节。

5.   结果交付：向用户输出可理解、可操作、可追溯的结果，包括说明、清单、建议、报告或下一步动作。

6.   验证与反馈：通过评测指标、样例数据、用户确认、日志、截图或视频证明结果有效。

7.   安全边界：对高风险行业判断、敏感数据、真实控制动作和专业决策进行明确限制与提示。


8.3 产品体验要求

    目标用户明确，交互入口清晰，用户能够理解如何开始、推进和完成任务；

    Demo 应展示真实流程，而不是只展示单轮问答或静态页面；

    输出内容应结构化、可阅读，并能解释依据、来源或处理逻辑；

    对失败、缺失信息、不确定结果和需要人工确认的节点有清楚提示；

    鼓励使用 Web、移动端、智能硬件、聊天界面、企业工具或行业系统中的自然产品形态。

12 常见问题 FAQ

Q1：无界应用赛道是否必须选择五个赛题之一？

原则上建议参赛团队从五大赛题中选择一个方向参赛。团队也可在赛题范围内自拟更细分的真实场景，但

应能够归入对应行业方向，并说明与赛题的关联。


Q2：作品必须开源吗？

GOAI 鼓励开源，但不强制所有作品完整公开开源。进入复赛 / 决赛后，参赛团队需要按组委会要求提供

评审可访问的代码、工程材料、Demo、运行证据或等价可验证材料。


Q3：可以使用商业大模型或闭源模型吗？

可以。除具体赛题另有要求外，参赛团队可根据作品需要选择开源模型、商业模型、平台模型或自研模型。

团队需在作品材料中说明模型来源、使用方式和关键能力。


Q4：可以使用第三方 Agent 框架或开发平台吗？

可以。参赛团队可使用 LangChain、LlamaIndex、AutoGen、Dify、Coze、ModelScope、百宝箱、灵

珠平台或其他工具平台。使用第三方平台时，应遵守对应平台规则和授权要求。


Q5：作品是否必须使用某个指定技术框架或工具？

不强制。参赛团队可围绕真实任务合理使用大模型、Agent 框架、知识库、工具调用、工作流编排、多模

态、记忆管理等能力。评审关注的不是技术名词堆叠，而是技术是否真正服务于任务闭环和用户体验。


Q6：可以只提交视频 Demo 吗？

不建议。视频 Demo 是必要材料之一，但参赛团队还应提交作品介绍文档、使用说明、技术架构说明、

数据来源与合规说明等材料。进入复赛 / 决赛后，还需提供可运行或可验证材料。


Q7：可以使用模拟数据吗？

可以。对于金融、教育、汽车、工业等领域，若真实数据不便开放，团队可使用公开数据、模拟数据、示

例数据或自建数据集。使用模拟数据时，应说明模拟逻辑、字段含义和适用边界。
                                 GOAI 无界应用｜Boundless Agents 参赛手册



Q8：可以接入真实业务系统吗？

可以，但必须确保数据授权、系统安全和合规边界。若涉及企业内部系统、真实用户数据、车辆数据、金

融数据、教育数据或工业数据，团队需提供必要说明，并承担相应合规责任。


Q9：AI+眼镜赛题必须使用实体眼镜吗？

不一定。参赛团队可使用 Rokid Glasses，也可使用模拟器进行开发和演示。具体硬件设备、模拟器、平

台权限及使用方式，以组委会及合作单位通知为准。


Q10：AI+汽车赛题能否做自动驾驶相关作品？

不建议做高风险驾驶控制或自动驾驶决策类作品。本赛题更关注车主服务、智能座舱、购车咨询、用车助

手、售后维保和出行规划等应用场景。


Q11：AI+金融赛题能否做投资建议或贷款审批？

不建议。金融类作品应定位为辅助分析、材料整理、流程引导、风险提示或信息检索，不应直接给出确定

性投资建议、贷款审批结果、保险赔付结论或替代金融机构决策。


Q12：AI+教育赛题能否直接给学生答案？

不建议。教育类作品更鼓励通过提示、追问、分步讲解、错因分析和同类练习帮助学习者理解知识，而不

是直接生成标准答案。


Q13：AI+工业制造赛题能否直接控制设备？

不建议。工业类作品应定位为辅助分析和建议系统，不应直接控制真实工业设备或替代现场安全生产决策。


Q14：参赛团队是否可以跨赛题提交多个作品？

具体规则以大赛官网通知为准。如允许多作品提交，团队应确保每个作品有清晰独立的场景、功能和提交

材料，避免重复包装同一项目。

附录 B：Agent 应用能力清单模板

字段               填写说明


应用入口             用户从哪里进入产品，例如 Web、移动端、眼镜、车机、聊天界面或企业系统。


目标用户             明确服务对象及其关键任务。


核心流程             从输入到结果交付的主要步骤。


Agent 能力         任务理解、计划生成、多轮交互、工具调用、知识增强、记忆、结果验证等能力。


工具 / 系统依赖        模型、API、数据库、知识库、硬件、第三方平台或业务系统。


输入输出             样例输入、输出结构、质量要求和展示方式。


失败处理             缺失信息、调用失败、不确定结果或高风险动作的处理方式。


安全边界             隐私、数据授权、行业风险、人工确认和不替代专业判断的说明。


运行证据             截图、视频、日志、评测指标、用户反馈或测试报告。
