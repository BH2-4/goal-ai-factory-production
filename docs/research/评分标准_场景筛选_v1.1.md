## 二、硬门槛（Gate，先于评分，任一不过即出局）

- **G1 数据/模板二选一门**：「模板可得」与「数据可得」**二者不可俱缺**——至少一项 ≥3 分（5 分制），否则该场景直接出局，不进入加权评分。
  - 数据可得：存在可用公开数据集，或可低成本自建模拟数据（含模拟逻辑说明，FAQ Q7 口径）
  - 模板可得：存在可复用的行业模板 / 演示模板 / 开源实现骨架（如 8D 报告模板、点检表模板、APS/RAG/工单系统开源模板），可作为 Demo 快速搭建的地基
- **G2 安全红线门**：场景涉及真实设备控制、替代安全生产/专业决策，且**无法**用"建议 + 人工确认"重构的 → 出局（手册 9.3、FAQ Q13）。

## 三、评分锚点（1~5 分制，保证 27 个场景打分一致性）

### D1 行业场景价值与代表性（25%）
子项：痛点真实强度 / 目标用户清晰度 / 可复制迁移性
- 5：痛点公认且高频（每天发生）、用户一句话说清、跨行业可迁移
- 3：痛点真实但中频、用户需解释、迁移需改造
- 1：伪痛点或极低频、用户模糊、强场景绑定

### D2 自主循环 + 决策边界契合度（20%）
子项：loop/graph 成形度 / 重大决策留人的自然度
- 5：天然存在持续值守循环或依赖图推理；重大决策（停线/召回/换供应商等）天然属于人
- 3：可构造触发式链路；决策边界需人工设计说明
- 1：只能做单轮问答式工具；Agent 被迫替人拍板或完全无事可做

### D3 数据可得性与 Demo 可落地性（15%）
子项：公开数据集 / 模拟构建成本 / 模板可得
- 5：有权威公开数据集（如 SECOM/AI4I）或有现成开源骨架，2 周内可出可运行 Demo
- 3：需自建模拟数据（工作量可控）或适配开源模板
- 1：数据/模板均需从零重造
（注：本维同时受 G1 硬门槛约束——数据与模板不可同时 <3）

### D4 差异化与竞争密度（20%）
子项：预期同类竞品密度 / 叙事稀缺度
- 5：预计同类作品极少，叙事在评审现场稀缺
- 3：有同类但角度可错位
- 1：红海方向（如通用维修问答、通用排产表）

### D5 安全合规边界清晰度（13%）
子项：边界表述天然清晰度 / 红线距离
- 5：纯建议域，边界一句话讲清，远离红线
- 3：涉安全域但可用"分级提示+人工确认"干净重构
- 1：贴红线（设备控制/替代专业判断）且重构牵强

### D6 多源融合 / 解释性潜力（7%）
子项：场景天然数据源数量 / 结论可解释空间
- 5：≥4 类天然数据源可融合；结论天然需要证据链（如根因、冲突解释）
- 3：2-3 类数据源；解释价值中等
- 1：单数据源、结论无需解释

## 四、使用规则

1. 27 个场景先过 G1/G2，再按 D1-D6 打分：总分 = Σ(维度分 × 权重) ÷ 5，满分 100
2. 每个 MVP 的 3 个候选场景中取总分最高者锚定其 PRD；分差 <3 分时以 D2（用户偏好）定夺
3. 打分结果全部留档（场景调研报告内附完整打分表），保证可溯源、可复算
4. 本标准与 MVP 价值层（v3：35/30/20/15）独立使用：v3 决定"做不做这个 MVP"，本标准决定"在哪个场景做"

## 五、执行口径默认值（沿用上轮确认）

- 场景粒度：「细分行业 × 环节」的具体实例
- PRD 深度：精炼完整（场景对比/Agent 编排/闭环 7 步/数据策略/评测指标/安全口径/三档排期/开源物/500 字简介），字段级细节留到最终选定后
- 输出顺序：P2 → P3 → P1
