## 二、作品层框架定义（v1.0）

| 维度 | 权重 | 评什么（依据 PRD 实际内容） |

| A 参赛竞争力 | 30% | 官方六维（25/25/20/15/10/5）在 PRD 落地形态上的综合兑现度 |

总分 = Σ(维度分 × 权重) ÷ 5，满分 100。

## 三、逐份打分（重读后依据）

### 1. M2-B 批次故障哨兵（PRD_M2B）—— 91.2 🥇
A4.7：场景价值高（批次问题厂商真痛）+跨工单闭环+技术深度（聚类×证据链）；B5.0：值守 loop 最纯正，召回/通报门禁业务原生（管理层决策本就存在）；C4.0：可独立交付（自含工单库+遥测+批次档案），但 PRD 自述依赖 M2-A 数据管线，需排期前置；D4.0：预埋批次剧本可证检出率，但仅 2 组模式、统计量小；E5.0：跨工单哨兵视角预计无同类。
**微循环**：事件流入→聚类→归因→8D 草稿全程自主 ✓ **宏门禁**：召回/通报/客户通知 100% 人工 ✓

### 2. M1-B Andon 值守循环（PRD_M1B）—— 89.9 🥈
A4.4：事件→分诊→派单→升级→复盘闭环最纯正，面板演示动态吸睛；B5.0：值守教科书+停线/结案门禁原生；C4.5：AI4I 驱动+事件模拟器，UI 中等；D4.5：AI4I 公开数据+分诊 ground truth+响应时长可量化；E4.0：Andon 工具成熟但 Agent 形态参赛少。
**本次排名跃升第一名（v3 第 6 → 第 2）**：锚定 AI4I 后证据变硬；升级策略 DSL 化后 loop 优势显性。

### 3. M3-A 齐套+插单冲突解释（PRD_M3A）—— 89.7 🥉
A4.7：LLM×求解器契约稳、动作包交付完整；B4.5：自动重算微循环+计划采纳/交期承诺门禁自然；C4.5：OR-Tools 确定性高、风险低；D5.0：**全场证据最硬**——齐套 100% 可程序校验、硬约束零违反可验、FIFO 基线可对比；E3.5：排产赛道拥挤，靠"冲突解释"错位但需防撞车。

### 4. M1-A 质量根因链（PRD_M1A）—— 86.6
A4.6：四源融合+证据链+8D 交付强；B4.0：触发式推理链深但 loop 感弱于值守型；C4.0：四表模拟器+可视化工作量中上；D5.0：SECOM 公开+注入式 ground truth；E4.0：质检参赛多、归因闭环少。
**角色建议**：根因引擎作为 M2-B 的内部模块实现（PRD 已自述复用），不必独立参赛。

### 5. M2-A 报修修复沉淀主链（PRD_M2A）—— 86.4
A4.6：业务闭环最深、双端体验好；B4.5：单票微循环+沉淀飞轮真实成立；C4.5（但 UI 面全场最大：双端×4 Agent）；D3.8：无公开数据集，ground truth 全自建；E3.8：维修问答竞品密度高，差异化靠执行兑现。

**角色建议**：转型为 M2-B 的**数据底座+决赛扩展旅程**（单票闭环演示在决赛作为哨兵的上游故事），不作为独立参赛主作品。

### 6. M1-E 沉淀飞轮（PRD_M1E）—— 85.5
A4.0：飞轮叙事独特但价值滞后（需对比演示才能感知）；B4.5：双微循环自主；C4.5：轻（预置案例+检索）；D4.0：复发剧本可证但样本小；E4.5：稀缺。**角色**：作为 M1-B 的收官模块（关闭→案例→复发预警），冻结独立参赛。

### 7. M3-C 供应商风险哨兵（PRD_M3C）—— 84.3

3. **第一备选：M1-B Andon 值守循环**（P1 备胎，89.9 分）——若 P2/P3 任一推进受阻即启用；其"关闭→案例→复发预警"收官模块吸收 M1-E
