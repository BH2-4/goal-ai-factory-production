## 1. 赛题主题（手册 4.3 节原文）

**AI+工业制造｜面向设备运维与供应链协同的工业 Agent**
重点验证：**设备、质量、工单、库存、排产和供应链协同**

官方给出的 5 个参考选题（手册 4.3.5，原文）：

1. **设备故障诊断 Agent**：基于传感器数据、报警记录、维修手册和历史工单辅助判断故障原因。
2. **质量异常分析 Agent**：关联质检数据、批次信息、工艺参数和生产记录定位异常来源。
3. **工单调度 Agent**：根据问题类型、人员技能、备件库存、紧急程度和产线状态生成分派建议。
4. **供应链风险预警 Agent**：基于订单、库存、供应商交付周期、物流状态和需求变化提示风险。
5. **生产计划辅助 Agent**：结合产能、物料、设备状态、人员排班和交期要求生成排产建议。

**边界要求（原文）**：如涉及安全生产、设备控制或现场操作建议，应明确提示仅作辅助参考，不替代专业人员判断和企业安全规范。
**FAQ Q13**：不建议直接控制设备；工业类作品应定位为**辅助分析和建议系统**。

**赛题个性化评审补充（手册 10.2，工业制造专属）**：重点看
**多源信息融合、流程闭环、解释性、可操作性和安全生产边界**。

> 切入点解读：这五个参考方向覆盖"设备-质量-工单-库存-排产-供应链"六要素，官方鼓励在赛题范围内自拟更细分场景（FAQ Q1），但需能归入工业方向。最有竞争力的切入点 = 六要素中取 2-3 个形成**跨域闭环**（如 设备诊断→工单调度→备件库存→排产调整），同时正面回应"多源信息融合 + 解释性 + 安全边界"三个个性化评审点。

## 3. 评审条件（手册 10 + 11 节）

### 3.1 通用评审维度与权重（10.1）

| 维度 | 权重 | 官方说明要点 |
|---|---|---|
| 行业场景价值 | **25%** | 真实、明确、有代表性的行业问题；目标用户/核心痛点/价值收益清楚；可复制迁移推广 |
| Agent 能力与任务闭环 | **25%** | 任务理解、多轮交互、计划生成、工具调用、知识增强、上下文记忆、结果交付；输入到验证的完整流程 |
| 产品体验与 Demo 完成度 | **20%** | 交互自然、流程清楚、反馈及时；Demo 稳定可运行，评委能快速验证核心价值 |
| 技术实现深度 | 15% | 合理使用大模型/Agent 框架/知识库/工具调用/多模态/工作流；架构清晰、工程可复现 |
| 安全、合规与可追溯 | 10% | 数据来源、使用边界、风险提示、合规约束；不替代专业人员/机构/主管部门最终判断 |
| 开放/复用贡献 | 5% | 可复用成果、模板、示例数据、文档、开源计划；协议与第三方依赖清晰 |

> 报名公告（8-10）配套解读原文：赛道先看"问题是否真实、场景是否扎实"，再看"Agent 是否真正参与解决问题、能否把流程走完"——这两项（共 50%）是"入场券"；"场景清晰、流程顺畅、证据完整的小闭环，远比功能庞杂却难以运行的大平台更有说服力"。

### 3.2 工业制造个性化补充（10.2）

多源信息融合、流程闭环、解释性、可操作性、安全生产边界。

### 3.3 红线与严重扣分项（11，逐条官方原文摘要）

1. 仅概念 PPT/营销材料、无可验证材料 → 原则上淘汰或严重扣分

4. 抄袭、套壳、伪造实验结果、刷社区数据、买 Star/Fork → 取消成绩
5. 数据/License/商业 API/闭源模型/个人信息等披露不实 → 扣分至追责
6. 作弊 → 取消资格与成绩
7. 不允许私下共享代码；雷同可取消成绩（需共享则合并队伍）
8. 高风险场景不得替代专业机构/现场人员最终判断

## 4. 作品要求（手册 1.3 / 08 / 09 章）

### 4.1 核心参赛要求（1.3）

- 至少完成**一个可演示、可验证的任务闭环**；说清目标用户、场景痛点、交互流程、技术路线、数据来源、合规边界、后续迭代计划
- 面向五大行业赛题之一（或一致的细分真实场景）
- 避免：泛问答、内容生成、无用户流程的概念展示
- 必须有：可运行 Demo、视频演示或等价可验证材料
- 说明：模型、Agent 架构、工具接口、知识库、数据处理与部署方式
- 明确：数据授权、隐私保护、风险提示、行业边界
- 鼓励：可开放复用的应用模板、工具组件、示例数据、技术文档

### 4.2 Agent 应用闭环 7 步（8.2，评审对照链路）

任务输入 → 意图理解 → 任务规划 → 能力调用 → 结果交付 → 验证与反馈 → 安全边界

### 4.3 技术要求要点（08 章）

- 8.1 五条基本要求：真实场景／Agent 能力（拒绝纯聊天、单轮问答、Prompt 演示）／任务闭环／可演示性／数据来源清晰＋边界表达清楚
- 8.3 产品体验：Demo 展示真实流程而非单轮问答或静态页；输出结构化、可解释依据；失败/缺信息/需人工确认节点有提示
- 8.4 知识库/RAG 要求：构建方式、检索策略、引用来源、更新机制、错误处理；上下文/记忆/状态管理说明
- 8.5 工具调用：调用方式、权限范围、返回处理、失败处理、用户可感知风险边界
- 8.6 多模态：工业等场景可重点体现多模态交互价值（加分方向）

### 4.4 开源、合规与安全（09 章）

| 项目 | 官方口径 |
|---|---|
| 开源代码 | 初赛不强制，需说明开放/复用计划；复赛起须提交可运行代码或等价工程材料＋评审可访问仓库 |
| 部署说明 | 复赛起必须：运行入口、依赖安装、配置方法、环境要求、复现实验说明 |
| 商业 API | 允许，须披露调用环节、费用假设、权限范围、可替代性与锁定风险 |

## 7. 对作品后续内容的决策建议（依据以上官方口径）

1. **48 小时内先交初赛两件套**（简介 ≤500 字 + 方案 PPT），按附录 A 结构组织；可选 3 分钟 Demo 视频显著增强"证据完整"印象。
2. **选题**：从 4.3.5 五个官方方向取 2-3 个组成闭环（推荐：设备故障诊断 → 工单调度 → 备件库存/排产联动；或质量异常分析 → 供应链风险预警），直接命中"多源信息融合、流程闭环、解释性、可操作性、安全边界"五个个性化评审点。
3. **简介/PPT 必答七问**（对应 50% 权重的两维）：目标用户是谁、场景痛点多真实、Agent 怎么理解需求、调用什么工具/知识、如何交付结果、异常与人工确认机制、落地迭代计划。
4. **技术上预留证据链**：日志、截图、评测指标、可追溯依据来源（对应 8.2 第 6 步与红线第 1 条）。
5. **合规口径写死**：辅助参考定位、不控制真实设备、不替代安全生产决策、数据用公开/模拟数据并说明模拟逻辑（FAQ Q7/Q13、9.3）。
6. **技术栈自由**：框架/模型不强制（FAQ Q3/Q4/Q5），可选 LangChain/Dify/Coze/ModelScope 等；多模态是工业场景明确加分项（8.6）。
