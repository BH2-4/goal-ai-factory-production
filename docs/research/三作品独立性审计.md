# 三作品独立性审计（B12 / B31 / B21 分三人独立提交）

> 日期：2026-08-14 ｜ 背景：D-015 三人三作品独立提交策略
> 目的：规避两条官方红线，保证三个作品以"清晰独立的项目"面目参赛

## 一、官方红线依据

1. **代码雷同红线**（手册 11 章原文）："不允许私下相互共享代码。如确需共享，应合并队伍；如发现代码雷同，组委会有权取消相关团队成绩。"
2. **差异化要求**（FAQ Q14）："如允许多作品提交，团队应确保每个作品有清晰独立的场景、功能和提交材料，避免重复包装同一项目。"（本策略为三人分别独立报名，非同队多作品，但差异化精神同样适用且更需自证）

## 二、三作品独立定位（对外面目）

| 维度 | B12 安灯中枢 | B31 Kit Pilot | B21 气脉助手 |
|---|---|---|---|
| 场景 | 机加车间（厂内运营） | 机械/汽配件（计划域） | 空压机厂商（售后域） |
| 用户 | 班组长/主管/工程师 | 计划员/物控/销售 | 厂商售后/客户设备管理员 |
| 核心动词 | **调度**（分诊派单升级） | **解释**（求解+冲突归因） | **问诊**（症状翻译+诊断） |
| 知识形态 | 异常案例（复发预警） | 排产偏好（规则候选） | 维修案例（诊断检索） |
| 交付物 | 处理卡+升级凭证+复盘 | 排产+解释+动作包 | 诊断卡+工单+案例 |
| 数据 | AI4I+事件流模拟 | 制造计划模拟生成器 | 模拟手册+维修工单生成器 |

## 三、功能重叠去重表（关键风险点）

| 重叠功能 | 归属裁决 | 差异化要求 |
|---|---|---|
| 案例沉淀 | **双主但域不同**：B12=车间异常案例；B21=售后维修案例 | schema 各写各的（字段集不同：B12 含事件类型/产线/SLA；B21 含故障码/备件/保内状态）；检索实现不同（B12 规则+向量混合，B21 CBR 相似度）；演示侧重不同（B12 演"复发对比 40min→5min"，B21 演"诊断引用历史工单"）；**术语区分**：B12 称"异常案例库"，B21 称"维修案例库" |
| 证据链表达 | 三作皆有，物不同 | **术语区分**：B12="升级凭证"；B31="约束日志"；B21="诊断依据"。UI 呈现形态差异化（凭证包/可点开日志/引用标注） |
| SLA/超时 | B12 主功能 | B21 仅"超时提醒"一行，不进 PPT 卖点页；B31 无此功能 |
| 请购/比价 | B31 主功能（动作包） | B21 仅"缺货请购卡"提示，无比价矩阵；B12 无此功能 |
| 照片多模态 | B12 分诊辅助 / B21 报修辅助 | 场景不同可共存；演示中各自的用法叙事不同（识别产线状态 vs 识别设备部件） |
| 规则统计预警 | B12 复发预警 / B21 同型热度 | 统计对象不同（故障码×车间 vs 故障码×机型机队）；阈值规则各自定义 |

## 四、实现独立性要求（硬性）

1. **三个独立仓库**（或同机不同目录互不引用），不共享任何源码文件
2. **不共享**：代码、配置、数据文件、Prompt 文件、README 模板句式
3. **可共享**：概念、公开方法论（RAG/OR-Tools/规则引擎）、公开数据集（AI4I 等各自自行下载）
4. 三套模拟数据生成器各自实现（字段、剧本、规模不同）
5. 三套 Demo UI 视觉明显区分（建议：B12 深色值守大屏风 / B31 浅色控制台风 / B21 双端产品风）
6. 提交材料：三份简介句式结构不同（已按各自版本撰写），PPT 版式不同

## 五、报名与队伍建议

- 三份独立报名：每人一队（可个人参赛，或各携 ≤3 人小队）；**初赛提交后成员锁定**
- 队伍命名建议体现各自项目（例：B12"安灯值守"、B31"Kit Pilot计划"、B21"气脉售后"——最终由三人自定）
- 意向行业赛题均为"AI+工业制造"，无冲突
- 三人各自的报名表单：https://yvq7lgbe.jsjform.com/f/miBrtl（详见 `submissions/提交要求调查_可溯源.md`）

## 六、风险与对策

| 风险 | 对策 |
