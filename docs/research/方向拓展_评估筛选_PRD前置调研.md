# 第三部分：入选 5 条的细节补充

## E. 质量异常根因分析 + 8D 报告 Agent（96 分）

- **定位一句话**：把"老师傅翻五个系统找质量异常原因"压缩成"Agent 自动关联追溯 + 根因假设 + 8D 报告初稿"。
- **目标用户/痛点**：离散制造（半导体/机加/注塑）质量工程师。痛点：SPC 告警后跨 QMS/MES/工艺/设备四套系统人工比对，定位一批异常根因平均数小时~数天；8D 报告写作占工程师大量时间。
- **Agent 编排（建议 4 个）**：① 异常检测值守 Agent（SPC/规则+时序模型）→ ② 数据侦探 Agent（多源数据拉取与对齐：批次谱系、工艺参数窗口、设备状态、来料检验）→ ③ 根因推理 Agent（假设生成→逐条验证→置信度排序，输出证据链）→ ④ 报告撰写 Agent（8D/CAPA 结构化初稿 D1-D8，附证据引用）。
- **闭环 7 步映射（手册 8.2）**：输入=SPC 告警/人工触发 → 意图理解=判定异常类型与影响面 → 规划=追溯计划 → 调用=QMS/MES/工艺库查询工具 → 交付=根因报告+8D 初稿 → 验证=回溯历史相似案例命中率+工程师确认 → 安全边界=仅辅助分析，不替代放行决策。
- **数据策略（公开数据集，避免合规风险）**：UCI **SECOM**（半导体制造 1567×591，含缺陷标签）做质量检出与特征归因；自建多表模拟数据集（批次谱系+工艺参数+设备日志，字段与模拟逻辑写进文档——FAQ Q7 口径）。评测指标：根因命中率（对模拟数据注入已知故障）、Top-K 归因准确率、报告采纳率。
- **解释性亮点（正面打个性化评审）**：每个根因结论带证据链（哪条参数越界、哪个批次共性、哪个设备时段相关），置信度分级，"未验证假设"单独列出。
- **安全边界口径**：建议措施需人工确认；涉及停线/放行决策明确"仅参考，不替代质量负责人判断"（9.3）。
- **Demo 形态**：Web 端"告警卡片→一键追溯→归因时间轴+相关性图→8D 报告导出"，3 分钟视频走一个完整案例。
- **开源复用物**：制造多表模拟数据生成器、根因推理 Prompt/工具链模板、8D 报告 schema。
- **风险与对策**：归因准确率被质疑 → 用注入式 ground truth 评测自证；报告太模板化 → 强调证据引用与人工修订闭环。

## A. 装备售后技术支持 Agent（92 分）

- **定位一句话**：装备制造商的"随身售后专家"——客户报修（含照片/语音）→ 多轮问诊 → 手册/案例检索 → 备件查询 → 工单派发 → 维修指导 → 案例沉淀回知识库。
- **目标用户/痛点**：中小装备制造商（空压机/注塑机/数控机床/光伏设备）的售后部门与终端客户操作工。痛点：现场工程师经验断层、专家差旅成本高、响应 SLA 难达标；每次维修的知识随人流失。
- **Agent 编排（4 个）**：① 问诊 Agent（多轮交互式故障树+症状照片识别）→ ② 知识检索 Agent（手册 RAG+历史工单案例推理 CBR）→ ③ 备件/工单 Agent（查库存、生成工单、建议工程师）→ ④ 沉淀 Agent（维修记录→结构化案例→回流知识库，越用越准）。
- **差异化关键（对抗"维修问答机"竞品）**：闭环终点不是"告诉用户答案"而是"工单+备件+指导+沉淀"——这是 25% 权重的"任务闭环"满分叙事；第 ④ 个 Agent 直接回应赛道关键词"经验沉淀"。
- **数据策略**：自建 2~3 本模拟设备手册（避免真实手册版权问题，手册 9.2）＋ 200 条模拟历史工单（含故障码/现象/措施/备件/耗时）；照片报修用公开设备图或拍摄实物。评测：问诊轮次效率、Top-3 诊断命中率、备件建议准确率、案例沉淀质量抽检。
- **多模态加分**：报修拍照→部件定位与状态识别；语音描述（现场戴手套打字难）。
- **安全边界口径**：涉及电气/机械操作给出分级提示，高风险步骤强制"联系持证人员"提示（远程指导安全边界）。
- **Demo 形态**：客户小程序/网页报修 + 售后工程师工作台双端，一个完整报修-修复-沉淀旅程。
- **开源复用物**：售后知识库 schema、故障树问诊 DSL、工单案例 CBR 模板。
- **风险与对策**：竞品多 → 用"双端业务流+沉淀飞轮"差异化；问诊容错 → 设计澄清与转人工节点（产品体验分）。

## F. Andon 现场异常响应 Agent（88 分）

- **定位一句话**：产线异常（设备报警/质量异常/缺料）从"现场吼人+微信群"升级为"自动分诊→找对人→开对单→跟踪到关闭→复盘沉淀"。
- **目标用户/痛点**：离散制造产线主管/班组长。痛点：异常响应链条长、责任漂移、事后无结构化数据、同类异常反复发生。
- **Agent 编排（4 个）**：① 分诊 Agent（告警流+现场照片/语音 → 分类与严重度分级）→ ② 调度 Agent（技能矩阵+班次+当前负荷 → 通知/升级策略）→ ③ 工单跟踪 Agent（超时升级、处理记录结构化）→ ④ 复盘 Agent（异常 Pareto、复发预警、SOP 修订建议）。
- **闭环 7 步**：事件输入 → 分级定类 → 响应计划（通知谁/备件/安全预案）→ 调用（排班表/备件/SOP 库）→ 交付（处理卡+工单）→ 验证（关闭确认+耗时统计）→ 安全边界（涉及停线的建议须人工执行）。
- **数据策略**：AI4I 2020 Predictive Maintenance（UCI，1 万条含 5 类故障模式合成数据）驱动设备告警演示；自建模拟排班/技能矩阵/事件流。评测：分诊准确率、平均响应时长（模拟对比）、复发率下降（模拟复盘）。
- **多模态加分**：现场照片（跑冒滴漏/异响录屏）辅助分诊——工业多模态的正面案例。
- **差异化**：与 A 共享"异常→工单→知识"骨架，但视角在厂内响应链而非厂商售后；两者数据与模块可复用。
- **风险**：事件流 Demo 需要做事件模拟器（工作量可控）；避免做成"通知机器人"——分诊规则与升级策略要有可解释输出。

## H. 非标文档结构化 NPI Agent（87 分，D 的垂直化形态）

- **定位一句话**：新品导入时的 BOM/图纸/工艺卡/验收标准等非标文档，自动解析→结构化预填→差异高亮→人工确认→发布到下游系统，消灭"AI 之前的数据搬运"。
- **目标用户/痛点**：制造企业工艺工程师/IE/计划员。痛点：客户来料文档格式五花八门，人工录入 ERP/MES 费时易错；这正是你说的"数据脏乱差挡住 AI 提效"的真实发生地。
- **Agent 编排（3 个）**：① 文档理解 Agent（版面分析+表格/字段抽取+图纸要素识别）→ ② 校验对齐 Agent（与 ERP 既有主数据匹配、单位/料号规范校验、冲突高亮）→ ③ 发布 Agent（生成待确认清单→人工审核→写入 mock 下游系统，全程留痕）。
- **闭环 7 步**：文档上传 → 类型/意图识别 → 解析计划 → OCR/表格/图纸工具调用 → 结构化结果+置信度 → 人工确认与修正回流 → 数据授权与留痕边界。
- **数据策略**：自造 20~30 份多格式样例（手写风格工艺卡、Excel BOM、PDF 图纸、邮件正文），版权干净；评测字段级准确率/召回率、人工修正量下降比例。
- **差异化亮点**：全场大概率没人做"给 AI 铺数据"的场景化作品；与官方"数据来源清晰"（8.1 第 5 条）天然呼应；解释性强（每个字段给来源坐标）。
- **风险**：图纸识别技术难度高 → 初期以表格/文本类文档为主，图纸做增强演示；场景价值分受映射度拖累 → 叙事上绑定"排产/质量的上游堵点"。

## B. 工业材料排产 Agent（85.5 分，压线入选）

- **定位一句话**：面向中小厂的"物料约束优先"排产助手——订单/forecast → 齐套检查（BOM 展开×库存×在途）→ 可行排产建议（LLM+求解器混合）→ 插单冲突解释与重排。
- **Agent 编排（3~4 个）**：① 齐套核算 Agent（MRP 逻辑：毛需求→净需求→缺口清单）→ ② 排产 Agent（OR-Tools/启发式求解，LLM 负责约束澄清与结果解释，不做数值计算）→ ③ 冲突解释 Agent（为什么这单被延后：缺哪个料/哪台机满负荷，给替代方案）→ （并入 C）④ 采购联动 Agent（缺口→请购建议→供应商交期风险提示）。
- **救分设计（针对两个扣分项）**：闭环弱 → 把交付物做成"可执行的动作包"（工单建议+请购单+交期承诺草案），不是一张表；竞争密度高 → 主打"插单场景+冲突解释"（解释性是个性化评审点，也是传统 APS 最缺的）。
- **数据策略**：自建模拟数据集（BOM 3 层、库存、在途、订单 30~50 单、产能日历），全部字段与逻辑写入合规文档。评测：齐套核算准确率、排产可行率（无违约束）、延期订单数对比基线规则、重排耗时。
- **技术叙事**：明确"LLM 不算数"——规划/澄清/解释归 LLM，最优化归求解器，两者契约清晰（技术实现深度 15% 的稳妥拿法，规避"LLM 排产不靠谱"质疑）。
- **风险**：评委问"和 APS 软件比呢" → 答案定位是"中小厂用不起 APS 的轻量入口+自然语言交互+解释性"；安全边界天然干净（纯建议）。

# 第四部分：组合建议与下一步

**建议最终保留 2 个出 PRD：E（质量根因+8D）与 A（售后技术支持）**，理由：
1. 分列 1、2 名且能力画像互补：E 吃"多源融合+解释性"，A 吃"业务闭环+沉淀飞轮"，撞车风险低；
