## 一、权重表（满分 100，v1.1 冻结，v1.2 未动权重）

| # | 维度 | 权重 | 修订依据 |
|---|---|---|---|
| 1 | 行业场景价值与代表性 | **25%** | 用户：适当降低（原 30） |
| 2 | 自主循环 + 决策边界契合度 | **20%** | 用户核心偏好，未动 |
| 3 | 数据可得性与 Demo 可落地性 | **15%** | 用户：降低（原 20）+ G1 硬门槛 |
| 4 | 差异化与竞争密度 | **20%** | 用户：提高（原 15） |
| 5 | 安全合规边界清晰度 | **13%** | 用户：稍微提高（原 10） |
| 6 | 多源融合 / 解释性潜力 | **7%** | 尾差归整（原 5） |

## 二、硬门槛（Gate，先于评分）

### G1 数据/模板二选一门（v1.1 冻结）
「模板可得」与「数据可得」**二者不可俱缺**——至少一项 ≥3 分（5 分制），否则该场景直接出局，不进入加权评分。
- 数据可得：存在可用公开数据集，或可低成本自建模拟数据（含模拟逻辑说明，FAQ Q7 口径）
- 模板可得：存在可复用的行业模板 / 演示模板 / 开源实现骨架（8D 报告模板、点检表模板、APS/RAG/工单系统开源模板等）

### G2 安全可重构门（v1.2 修订：不再是绝对否决）
场景触碰真实设备控制、安全生产或专业决策替代时，**不直接出局**，改为按以下模式评估其**可重构性**：

> **微循环自主、宏流程门禁**
> - **极小闭环（micro-loop）**：Agent 自主完成完整的微小任务循环——发现、拉数、分析、起草、准备动作包；
> - **大流水线（macro-pipeline）**：关键节点设**人工门禁**（审核点、放行点），**终点重大决策必须人工确认**（放行/召回/停线/采纳计划/切换供应商等）。

判定规则：
- **可重构**（能按上述双层模式干净落位）→ 正常进入评分，且 D5 按"重构后形态"打分（重构自然=高分）
- **部分可重构**（需绕行或削弱核心价值才能落位）→ 进入评分但 D5 扣分（≤2 分）
- **不可约简的红线**（必须直接驱动真实设备动作、必须替人做安全决策且无法门禁化）→ 出局

依据：用户指示（2026-08-14）＋手册 8.1-6「人工确认机制」、9.3 行业边界、FAQ Q13——比 v1.1 更精细且与官方口径一致。

## 三、评分锚点（1~5 分制）

### D1 行业场景价值与代表性（25%）
子项：痛点真实强度 / 目标用户清晰度 / 可复制迁移性
- 5：痛点公认且高频（每天发生）、用户一句话说清、跨行业可迁移
- 3：痛点真实但中频、用户需解释、迁移需改造
- 1：伪痛点或极低频、用户模糊、强场景绑定

### D2 自主循环 + 决策边界契合度（20%，v1.2 细化）
子项：**微循环成形度** / **宏门禁落位自然度**
- 5：微循环天然存在（持续值守 loop 或依赖图推理可自主跑完）；重大决策天然属于人、门禁点在业务流程中本来就有（签字/审批/放行环节）
- 3：微循环可构造（触发式链路）；门禁点需人为设计并解释
- 1：只能做单轮问答式工具（无微循环可言）；或 Agent 被迫替人拍板 / 完全无事可做

### D3 数据可得性与 Demo 可落地性（15%）
子项：公开数据集 / 模拟构建成本 / 模板可得
- 5：有权威公开数据集（如 SECOM/AI4I）或现成开源骨架，2 周内可出可运行 Demo
- 3：需自建模拟数据（工作量可控）或适配开源模板
- 1：数据/模板均需从零重造
（本维受 G1 硬门槛约束——数据与模板不可同时 <3）

### D4 差异化与竞争密度（20%）
子项：预期同类竞品密度 / 叙事稀缺度
- 5：预计同类作品极少，叙事在评审现场稀缺
- 3：有同类但角度可错位
- 1：红海方向（如通用维修问答、通用排产表）

### D5 安全合规边界清晰度（13%，v1.2 联动 G2）
子项：按 G2 重构后的边界表述清晰度 / 红线距离
- 5：纯建议域或重构自然，边界一句话讲清（"微循环全自动、终点人拍板"），远离红线
- 3：涉安全域但可用"分级提示+人工确认"干净重构
- 2 以下：需绕行或削弱核心价值才能落位（对应 G2 部分可重构）

### D6 多源融合 / 解释性潜力（7%）
子项：场景天然数据源数量 / 结论可解释空间
- 5：≥4 类天然数据源可融合；结论天然需要证据链（如根因、冲突解释）
- 3：2-3 类数据源；解释价值中等
- 1：单数据源、结论无需解释

## 四、使用规则

1. 27 个场景先过 G1/G2，再按 D1-D6 打分：总分 = Σ(维度分 × 权重) ÷ 5，满分 100
2. 每个 MVP 的 3 个候选场景中取总分最高者锚定其 PRD；**分差 <3 分时以 D2（用户偏好）定夺**
3. 打分结果全部留档（场景调研报告内附完整打分表），保证可溯源、可复算
4. 两层标准独立使用：v3 分数决定"做不做这个 MVP"，本标准决定"在哪个场景做"

## 五、执行口径默认值（已确认）

- 场景粒度：「细分行业 × 环节」的具体实例
- PRD 深度：精炼完整（场景对比/Agent 编排/闭环 7 步/数据策略/评测指标/安全口径/三档排期/开源物/500 字简介），字段级细节留到最终选定后
- 输出顺序：P2 → P3 → P1
