01 场景锚定

场景锚定

选 S04：跨工单哨兵视角差异化最强；与 S01/M2-A 同数据域（工单+遥测），管线复用。落选理由：S05 偏能源叙事稀释装备售后主线；S06 监管门禁刚性（G2 部分可重构）。

对应 PRD §1 场景锚定

02 目标用户与痛点

目标用户与痛点

  • 用户：空压机厂商质量负责人、售后负责人（管理数千台分布客户机队）。
  • 痛点（量化假设，实现期校准）：批次性问题平均在第 N 起投诉后才被识别；召回/服务通报决策缺影响面数据；机队信息散落在监控系统与工单系统两处。
对应 PRD §3 用户与痛点

03 产品定位

产品定位（一句话）

厂商的机队哨兵：持续盯全渠道工单与遥测流，发现批次性故障模式后自主起草售后 8D 与影响面清单，把"客户投诉倒逼发现"变成"厂商主动发现"。

对应 PRD §2 产品定位

04 Agent 编排 · 微循环与宏门禁

Agent 编排（3 Agent）

Agent职责（微循环内自主）
聚类监测 Agent新工单/告警 embedding → 故障码与话题聚类 → 时间/批次/地域聚集度检测（持续值守）
根因推理 Agent复用 M1-A 证据链引擎：工单×故障码×批次档案×遥测四源 → 批次假设逐条验证
报告起草 Agent售后 8D 初稿（D1-D5）+ 影响面清单（客户/机台/批次）+ 服务通报建议
  • 微循环定义：从新事件流入到"模式警报 + 8D 草稿 + 影响面清单"生成，全程无人工介入。
  • 宏门禁点：①是否发服务通报/召回（厂商管理层）②客户通知（售后经理）③8D 定稿。
对应 PRD §4 Agent 编排

任务闭环 7 步映射（手册 8.2）

输入=工单/告警流 → 意图理解=事件分类与聚集度评估 → 任务规划=追溯与验证计划 → 能力调用=工单库/遥测/批次档案查询 → 结果交付=模式警报+8D 初稿+影响面清单 → 验证反馈=已知批次剧本回放命中率 → 安全边界=召回类重大决策全部人工。

对应 PRD §5 闭环 7 步（手册 8.2）

06 数据策略 ＆ 评测指标

数据策略

200+ 条模拟工单（预埋 2 组批次模式：同批次部件失效、同固件版本缺陷）+ 类 AI4I 遥测合成数据；批次档案复用 M2-C 输出。模拟逻辑与 ground truth 写入合规文档（FAQ Q7）。

评测指标

已知批次模式检出率 2/2（召回 100%）；误报 ≤1 次/模拟周；检出提前量较"投诉阈值"基线提升 ≥3 天（模拟口径）；8D 初稿采纳率（人工评分 ≥4/5）。

对应 PRD §6 数据策略 ＋ §7 评测指标

07 安全合规口径

安全合规口径

仅监测与起草，不触发任何自动客户动作；召回、服务通报、客户通报决策权在厂商（手册 9.3、FAQ Q13）；数据全模拟并披露生成逻辑。

对应 PRD §8 安全合规

10 参赛简介（≤500 字 · 八要素）

参赛简介（≤500 字，八要素）

项目名称：气脉哨兵 AirSentinel——装备机队批次故障预警智能体。

行业赛题：AI+工业制造。目标用户：空压机厂商质量与售后负责人。

核心问题：批次性故障靠客户投诉倒逼才发现，召回决策缺乏影响面数据支撑。

解决方案：跨工单持续值守的三 Agent 系统——聚类监测 Agent 持续聚合全渠道工单与遥测流，识别同型故障率异常与批次聚集；根因推理 Agent 融合工单、故障码、批次档案与遥测四源生成证据链；报告起草 Agent 自动产出影响面清单与售后 8D 初稿。

创新点：微循环自主、宏流程门禁——Agent 自主完成发现、验证与起草，召回、服务通报与客户通知等重大决策始终由厂商拍板；从"处理单票"升维到"盯住全局"。

开放/复用价值：开源批次模式检测管线、售后 8D 模板与事件流模拟器，可迁移至其他装备机队。

当前进展：方案设计完成，原型开发中，提交时附回放演示。

对应 PRD §12 参赛简介
